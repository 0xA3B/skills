# README

A README is a gateway: it orients the reader, gets them to a first working result, and links to
deeper material. Keep it user-facing and short. Move maintainer detail to CONTRIBUTING, move deep
reference out of the file, and link to both.

## Section order

Use this order, and include a section only when it has real content:

1. Title, then one sentence that states what the project does and for whom.
2. A short paragraph on the problem the project solves. Three sentences or fewer.
3. Requirements the reader must have before installation.
4. Installation, with the smallest supported path first.
5. Usage, with the smallest working example first, then the most common tasks.
6. Configuration, as a table of options, when the project has meaningful configuration.
7. Pointers: full documentation, contributing guide, and license.

## Rules

- The reader must reach a first working result without leaving the README and its links.
- State prerequisites before the commands that need them.
- Keep the roadmap, the changelog, and the full API out of the README; link to them instead.
- Keep badges few and informative, such as build status, published version, and license.
- Do not add empty ceremony sections, such as a "Contributing" heading that only says "contributions
  welcome".

## Completion

The README is done when a new reader can state what the project does, install it, and complete one
task, using only this file and its links.
